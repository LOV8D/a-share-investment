# 腾讯云部署操作手册

目标架构很简单：一台腾讯云 Linux 服务器上运行三个 Docker 容器。

- `app`：投资工作台和 API，只在 Docker 内部监听 8765。
- `scheduler`：北京时间每天 00:00 调用一次完整模拟盘流水线，处理最近一个已结束交易日；失败后当天不自动重试。
- `caddy`：唯一对公网开放的入口，提供 HTTPS、用户名密码和安全响应头。

数据、模拟账户和运行报告都保存在服务器目录中，重启容器不会丢失。产品不会连接券商或真实下单。

### 2. 配防火墙

在腾讯云控制台进入该实例的“防火墙”。轻量 Linux 应用模板通常默认放通22和80，但443需要检查并通常要补一条规则。按下表检查/添加入站规则：

| 端口 | 来源 | 用途 |
|---|---|---|
| TCP 80 | `0.0.0.0/0` | 域名证书签发和跳转 |
| TCP 443 | `0.0.0.0/0` | 投资工作台 HTTPS |
| TCP 22 | 仅你的固定公网 IP（若不固定，先保留平台默认规则） | 新服务器 SSH |

不要开放 8765。它只供 Caddy 在 Docker 内访问。

### 3. 选择访问地址

有域名时，把所需主机名的 A 记录指向服务器公网 IP。域名模式由 Caddy 自动申请可信 HTTPS 证书。**当前实例位于北京；域名正式指向中国内地服务器前，须先完成 ICP 备案或腾讯云接入备案。**首次备案要求轻量服务器购买时长至少 3 个月且备案期间剩余至少 30 天，因此目前购买的 1 个月实例暂不能用于首次备案。完成备案后才能执行下面的域名部署命令。详见[腾讯云轻量服务器备案说明](https://cloud.tencent.com/document/product/1207/45756)。

暂时没有域名也能用 `https://服务器IP`。系统会生成内部证书，第一次打开时浏览器会显示证书不受信任；这是 IP 模式的正常限制，用户名密码和传输加密仍然存在。正式长期使用建议绑定域名。

## 一条命令部署

在这台 Mac 的终端执行：

```bash
cd "/Users/watson/Documents/ChatGPT/Investment/A share investment"
DEPLOY_HOST=49.233.170.147 ./scripts/deploy_tencent.sh
```

域名模式改为：

```bash
DEPLOY_HOST=49.233.170.147 APP_SITE=invest.example.com ./scripts/deploy_tencent.sh
```

脚本会自动完成：

1. 上传代码和 2026-08-31 冻结历史库；
2. 第一次部署时上传当前前向数据、模拟账户和最近一次已验收研究结果，但跳过不影响网页的超大逐行预测文件；
3. 首次部署时在服务器生成随机网页密码和 Caddy 密码哈希；以后切换域名或更新代码都保留原密码；
4. 构建镜像并启动三个容器；
5. 保留 `data/`、`runs/`、Caddy证书和配置为持久目录。

部署结束后读取一次登录信息：

```bash
ssh -i ~/.ssh/a_share_investment_tencent ubuntu@49.233.170.147 'cat /home/ubuntu/a-share-investment/deployment-credentials.txt'
```

登录信息只保存在服务器，文件权限为 600。记入密码管理器后可以删除该明文文件。

## 上线验收

先在服务器查看容器：

```bash
cd /home/ubuntu/a-share-investment
sudo docker compose ps
sudo docker compose logs --tail=100 app scheduler caddy
```

三个容器应为 `Up`，`app` 应显示 `healthy`。然后打开你的 HTTPS 地址，输入 `investor` 和部署时生成的随机密码。

在网页“数据中心”应能看到：

- 历史研究截止日为 2026-08-31；
- 最新实时信号日和下一交易日；
- 沪深300成分为 300；
- 最新行情覆盖率为 100%；
- 自动采集来源及警告。

可在服务器手工做一次完整演练：

```bash
sudo docker compose run --rm app python -m ashare paper
```

同一信号日已经成功时，命令只会提示“没有新的交易日”，不会重复生成订单。确需调试才加 `--force`。

## 每晚自动运行

`scheduler` 容器常驻。它使用 `Asia/Shanghai` 时区，每天 00:00 尝试一次。实际是否产生新计划还取决于交易日历、新行情和同日幂等状态，所以法定节假日不会产生重复计划。

查看最近调度日志：

```bash
sudo docker compose logs --tail=200 scheduler
cat runs/paper_schedule.json
cat data/live/collection_status.json
```

任务失败时不会发布半套数据，也不会延用过期计划；当天不自动重试，可在网页手动运行。网页中的最近成功报告保持可读。

## 备份与恢复

最重要的前向状态是 `data/live/` 和 `runs/`。每周或改参数前在服务器执行：

```bash
cd /home/ubuntu/a-share-investment
tar -czf "$HOME/a-share-investment-backup-$(date +%F).tar.gz" data/live runs config.json .env
```

下载到本机后再删除服务器上的旧压缩包。恢复时先停止容器，把压缩包解回同一目录，再执行 `sudo docker compose up -d`。

## 常见问题

**网页打不开：** 先检查腾讯云 80/443 入站规则，再看 `sudo docker compose ps` 和 Caddy 日志。

**镜像拉取超时：** 优先使用腾讯云 Docker 应用模板或配置腾讯云镜像加速；本项目不依赖本机 Docker 才能部署。

**当天没有新计划：** 查看 `collection_status.json`。节假日、00:00 自动任务尚未运行或同一信号日已成功时不会产生新订单；公开源尚未更新时，当天可手动运行或等待次日00:00。

**某个新闻/论坛源失败：** 文本当前只是观察层，会留下警告；结构化行情、300只成分和交易日历通过时仍可评分。

**行情或股票池不完整：** 这是硬失败。系统不发布新数据、不生成订单；修复后手动运行，或等待次日00:00。
