# 研究设计与当前实现

截至2026-09-20。这个产品的目标是以可检验的研究流程寻找收益预测增量；历史回测已经完成，但所用历史已参与开发，不能据此认定存在可复制 alpha。

## 已实现

1. CSV/Parquet导入、显式供应商列映射与单位换算、字段和时间质量检查、输入哈希、运行清单。
2. 当日历史成分、财务按可用时间向后连接、修订记录、标签成熟时间和交易日历约束。
3. 13个量价因子 + 10个基本面/数据时效因子 + 5个文本事件因子；横截面排名归一化、不使用全样本均值。
4. 生产分数固定组合价值、质量、低风险和短期反转因子。LightGBM LambdaRank 与 Ridge 作为挑战者滚动训练；时间隔离、只使用已结束的收益标签，TreeSHAP只解释树挑战者。
5. 界面默认6个经济直觉的代数组合；CLI提供默认32个有预算限制的因子候选实验和可选LLM提议接口，训练区间内部按时间发现/验证，跨界标签剔除。表达式经AST白名单解释，只允许注册特征与有限代数运算；不执行任何AI生成的Python。真实LLM提议需要模型配置，本次未调用。
6. 本地Ollama、兼容Chat Completions模型抽取器：要求JSON、验证数值范围与原文连续引用，失败拒绝、三种时间和哈希留档。RSS是受限单源采集器，学校数据以导出接入。
7. 文本感知的第二模型与有限权重融合；默认关闭。在真实数据和独立样本外证据到位前，AI事件仅观察。
8. 长仓、无杠杆、Top K+持仓缓冲、逆波动权重、单股/行业绝对上限、现金、周频调仓、双边换手、最小经济交易金额、ADV参与率、整数申报、次日开盘条件限价、停牌、方向性涨跌停、T+1、费用、滑点。
9. 逐日成交日志、净值、IR/Sharpe/回撤/跟踪误差/换手/费用、日期分块IC区间、LightGBM/Ridge挑战者和双倍成本压力测试。
10. 每日运行CLI、等待真实当日数据的本地定时器、本地界面、导入、参数编辑、次日计划下载；开盘竞价预检命令。未接券商。

## 为何先用这套模型

真实回测中，原70% LightGBM + 30% Ridge组合的 Rank IC 只有0.0013，日频换手又使10万元账户累计费用接近本金，因此被否决。固定经济含义的生产因子组在同一数据上更稳定、成本更低；复杂模型保留为挑战者，只有冻结后的前向样本证明净增量才可晋升。微软Qlib也提供Alpha158和LightGBM等研究基线；本项目是独立实现的轻量引擎，**没有安装或声称已经集成Qlib/RD-Agent**。[Qlib](https://github.com/microsoft/qlib)、[LightGBM LambdaRank](https://lightgbm.readthedocs.io/en/stable/pythonapi/lightgbm.LGBMRanker.html)

RD-Agent的因子/模型自动研究值得作为后续挑战者：需限定数据窗口、执行隔离、实验预算、冻结测试集和记录失败实验。[微软研究说明](https://www.microsoft.com/en-us/research/articles/rd-agent-quant/)。这里没有用“最先进”替代真实回测验收。

LLM擅长把原文转换成可检查的结构；最终交易由可复现模型和约束生成。Ollama支持结构化输出，可在本机运行具备中文财经理解能力的模型；模型名称由实际安装和提取评测决定，不写死一个未经本机验证的“最佳模型”。[Ollama结构化输出文档](https://docs.ollama.com/capabilities/structured-outputs)

## 决策时钟

- 每天00:00中国时间尝试一次，处理最近一个已结束交易日；信号只使用该交易日23:59:59前已经公开、抓取并处理的数据。失败后当天不自动重试，可在网页手动运行。
- 截止后的新闻放到下一次运行。当前不自动运行一个隔夜新闻更新决策层；开盘预检检查成交条件。
- 信号 t 的训练目标：`复权open(t+1+h) / 复权open(t+1) - 1`，h默认5；减当日截面平均收益作Ridge标签，LambdaRank使用5档相关性标签。
- `label_end`与该价格可用时间必须早于训练边界。训练边界额外退让embargo_days；按时间训练，不随机拆分股票行。
- 预测窗口每天推进，生产排名每天更新；默认只在每周最后一个交易日下调仓计划。研究回测每20个交易日重训ML挑战者；`daily`会重新拟合最新挑战者窗口。
- 模型评分是相对排名，不是上涨概率、预期收益率或确定性承诺。

## 两类信息如何结合

文本特征 = 来源权重 × 置信度 × 重要性 × 新颖度 × 指数时间衰减，再按证券聚合。来源示例权重：公告1、政策0.9、新闻0.7、论坛0.2；这些是预先声明的研究假设，未宣称最优。

结构化生产分数：盈利收益率、账面市值比、现金流收益率、ROE、毛利率和短期反转构成正向篮子；应计利润、杠杆、波动、下行波动、换手和振幅构成风险篮子。两组先在当日截面内排名，再等权相减。LightGBM 与 Ridge 的分数独立保存并做同口径成交回测，不进入当前订单。

启用文本实验时，文本感知树模型仍只属于实验路径。低覆盖时不启用；当前真实运行文本权重为0。原文风险事件可查看，但本版本不把情绪标签直接当买卖命令。

需要比较相同时间窗口、相同费用和相同股票池下：结构化、文本融合、线性基线、双倍成本。当前有前者的实现，不等于已经证明文本增量。政策证券映射、近义事件去重、嵌入语义新颖度尚未实现；目前按证券+内容哈希精确去重。

## 真实数据研究协议

2010–2026 的整段历史已经用于发现原模型失败、选择低换手规则和确定10万元账户参数，因此已经被消耗，不能再称为一次性最终保留期。当前报告仍是逐期仅用过去数据训练/评分的滚动样本外结果，但规则层面的选择看过整段成绩。下一份有效证据必须来自冻结版本后的新数据，建议至少60个交易日。

先登记因子经济解释、方向、持有期、交易成本、试验次数。不能看测试期IC再调参数并继续把同一测试期叫“未见样本”。进一步可使用分组消融、按市场阶段稳定性、行业中性化、交易成本/容量检验、Deflated Sharpe和多重检验；当前CI只用日期分块bootstrap，未实现这些检验的全部算法。

上线前至少需要：真实数据通过逐表核对；一个独立未参与选择的保留期；实际账户费用与竞价成交校准；冻结模型后至少60个交易日的前向模拟；数据晚到和任务失败演练；与券商核查板块权限和程序化交易报送流程。深交所程序化管理细则于2025-07-07实施，最终接券商前需按实际业务确认适用要求。[深交所规则通知](https://www.szse.cn/lawrules/rule/trade/t20250403_612770.html)

这些是研究产品的验收步骤；没有自动替你提交报送或订单。

## 10万元账户的持仓数与成本

25只等权时每只约4,000元，最低5元佣金单边已达12.5bp，且许多高价股在100股/200股最低申报和5%权重上限下根本无法持有。真实回测证实这种配置会产生大量小额交易。

当前默认目标15只、单股7%、行业28%、排名缓冲15名、周频调仓、调仓日双边换手15%。普通调整至少为净值2.5%；只有清仓残余股可低于门槛。计划层和执行层都会复核，防止预算截断后重新产生高费率小单。产品展示全体排名、可实现目标、整手后权重、排除原因和条件订单。

## 执行模型的实质限制

- 只模拟开盘成交，使用日线open加减固定滑点；无法重建集合竞价排队、盘中流动性或真实冲击。开盘触及买入涨停/卖出跌停保守不成交。
- 买入在现金、单股与行业约束下再次检查，卖出未成交不会当成到账现金。当日新增股份不可当日卖出。
- 当日成交额不会拿来决定收盘前下单量；量能预算用过去20日成交额。
- 公司行动支持普通现金分红与送转。除息即现金可用会高估真实可交易现金，未计红利税；复杂配股、权证、合并、退市清算尚未实现。不得把这些缺口下的结果标成可实盘。
- 风控是绝对权重上限，**不是**沪深300行业/市值中性、Barra风险模型、协方差优化或Beta对冲。本版本不做融资融券、期货、期权。
- 缺失行情不默认归零或填成盈利；持仓缺少行情时停止，并要求补齐。
- 本地服务只监听127.0.0.1。没有用户认证，不应直接公开映射到互联网。
